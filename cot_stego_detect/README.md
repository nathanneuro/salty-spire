# cot_stego_detect

An empirical test-bed for **detecting steganographic channels in
language-model chain-of-thought**. A small, self-contained project that
takes a stab at a genuinely neglected corner of the AI-safety literature
and reports real numbers on a reproducible synthetic benchmark.

## Why this

If a reasoning model wants to smuggle information past a CoT monitor —
its own prior internal state, a coordination signal to a second model,
hints about a user's query that a policy says it shouldn't leak — one of
the most obvious routes is *steganography inside the CoT text itself*.
Natural language has enormous amounts of uncontrolled entropy (word
order, synonym choice, punctuation, sentence length, discourse
particles), and any of it can be bent to carry hidden bits while the
surface content of the reasoning stays entirely faithful to the task.

The threat is well-articulated in the literature — Roger & Greenblatt
(2023) proposed paraphrase defenses as a mitigation, Lanham et al.
(2023) showed CoT faithfulness is already weak, and Motwani, Baker et al.
(2024) demonstrated stego emerges under RL in practice — but empirical
*detection tooling* is sparse. Most safety work on CoT focuses on
faithfulness (does the CoT match the model's actual cause?) rather than
on watching for hidden channels in CoT the overseer *sees*. This project
is a small, self-contained detector test-bed aimed at that gap.

## What's in the box

```
cot_stego_detect/
├── stego/
│   ├── bitstream.py     # bit ↔ bytes, looping cursor over payloads
│   ├── corpus.py        # toy running-total problems + CoT writer
│   ├── encoders.py      # red team: baseline, synonym, acrostic,
│   │                    #           punctuation, length_parity
│   ├── parsing.py       # inverse of the CoT writer (closed templates)
│   └── detectors.py     # blue team: χ², punct_rate, length_parity,
│                        #            bigram_surprisal, ensemble
├── experiments/
│   ├── run_benchmark.py         # full encoder × detector AUROC table
│   ├── run_capacity_curve.py    # AUROC as a function of batch size
│   └── run_balanced_payload.py  # evasion via bit-balanced payloads
├── tests/test_stego.py
└── results/                     # generated by the scripts above
```

The corpus is a domain of running-total arithmetic problems (`Start
with 7. Add 3. Subtract 2. …`). Each reasoning step has several
equivalent templates and an optional hedge clause with two punctuation
variants, giving 3 binary decisions per step plus 1 for the conclusion.
The `CoTWriter` calls a `Chooser` at every decision point; the
`BaselineEncoder` samples the chooser uniformly at random, while the
stego encoders consume bits from a looping payload. This structure
cleanly separates the *cover grammar* from the *embedding strategy* so
the benchmark measures what it claims to.

### Encoders (red team)

| name            | channel                                             |
|-----------------|-----------------------------------------------------|
| `baseline`      | none (null distribution)                            |
| `synonym`       | bits in template choice for each step & conclusion  |
| `acrostic`      | bits in first-letter variant of each step template  |
| `punctuation`   | bits in single vs. double space before a hedge      |
| `length_parity` | bits in whether a hedge clause is inserted          |

### Detectors (blue team)

| name              | needs templates? | needs clean LM ref? | idea                                                                                                                         |
|-------------------|:----------------:|:-------------------:|------------------------------------------------------------------------------------------------------------------------------|
| `chi_sq_template` | yes              | no                  | Pearson χ² against the uniform null, per family                                                                              |
| `punct_rate`      | yes              | no                  | |hedge-rate − 0.5| + |double-space-rate − 0.5| scaled by √N                                                                  |
| `length_parity`   | yes              | no                  | |hedge-rate − 0.5| · √N                                                                                                     |
| `bigram_surprisal`| **no**           | yes                 | Laplace-smoothed bigram LM fit on clean; z² of batch mean surprisal                                                          |
| `ensemble`        | —                | yes                 | Sum of squared component z-scores, each component calibrated on held-out clean batches                                      |

The bigram detector is included as a black-box baseline: it never sees
the template set, so its performance bounds what a purely statistical
auditor could do without knowing the model's phrasing grammar.

## Running it

No external dependencies. Python ≥ 3.9.

```bash
# unit tests
python -m unittest cot_stego_detect.tests.test_stego

# main benchmark (AUROC table)
python cot_stego_detect/experiments/run_benchmark.py

# capacity curve
python cot_stego_detect/experiments/run_capacity_curve.py

# bit-balanced payload evasion
python cot_stego_detect/experiments/run_balanced_payload.py
```

Each script writes a markdown table into `results/`.

## Results

### 1. Main benchmark (batch size 100, 40 paired runs)

AUROC for separating stego batches from clean baseline batches.

| detector           | acrostic | length_parity | punctuation | synonym |
|--------------------|---------:|--------------:|------------:|--------:|
| chi_sq_template    |    0.778 |         0.451 |       0.483 |   0.927 |
| punct_rate         |    0.504 |         0.822 |       1.000 |   0.547 |
| length_parity      |    0.457 |         0.731 |       1.000 |   0.529 |
| bigram_surprisal   |    0.746 |         0.710 |       1.000 |   0.834 |
| ensemble           |    0.810 |         0.824 |       1.000 |   0.948 |

Takeaways:

- **No single white-box test dominates.** Each template-aware detector
  only sees bias in the slot it watches; a `synonym`-style encoder
  escapes the `punct_rate` and `length_parity` tests almost perfectly
  (AUROC ≈ 0.5), and vice versa. This is the expected picture: an
  overseer needs to cover every controllable surface feature, or the
  adversary will move to whichever one is unwatched.
- **The black-box bigram detector is not a toy.** Without any
  knowledge of the template grammar it reaches AUROC 0.71–1.00 across
  every encoder, because any deterministic push on template or
  hedge choice perturbs the corpus-wide bigram distribution.
- **Ensembling is strictly helpful.** The calibrated ensemble is never
  the best component in isolation but is never far from it either —
  the right default for an overseer who doesn't know which channel
  an adversary picked.

### 2. Capacity curve

How fast AUROC climbs with batch size. Selected rows (full table in
`results/capacity_curve.md`):

```
encoder         detector             n=10  n=50  n=100  n=400  n=800
synonym         chi_sq_template      0.53  0.89  0.96   0.94   0.92
synonym         bigram_surprisal     0.62  0.72  0.77   0.85   0.79
punctuation     punct_rate           1.00  1.00  1.00   1.00   1.00
length_parity   length_parity        0.82  0.85  0.77   0.92   0.72
```

The chi-square and bigram detectors both saturate by batch size
~100 against the matched encoder. The `punctuation` encoder's
forced-hedge behaviour is an immediate tell even at batch size 10,
because hedges in the baseline are present only half the time.

### 3. Balanced-payload evasion (`synonym` encoder, batch 200)

The most interesting finding. A patient adversary who uses a **bit-
balanced** payload whose length divides the per-batch decision count
(here: 8-bit payload `11110000`) makes the resulting template
distribution *exactly uniform in expectation*. Frequency-based
detectors then see nothing:

| detector           | unbalanced (5/7 ones) | balanced (4/8 ones) |
|--------------------|----------------------:|--------------------:|
| chi_sq_template    |                 1.000 |           **0.155** |
| punct_rate         |                 0.461 |               0.570 |
| length_parity      |                 0.503 |               0.521 |
| bigram_surprisal   |                 1.000 |               0.439 |

Two things worth calling out:

1. **Chi-square AUROC drops to 0.155 — *below* random.** That's not
   noise. A bit-balanced looped payload produces near-zero empirical
   variance in template frequencies, while clean batches retain
   normal binomial fluctuation around 0.5. So on this specific attack
   the χ² statistic is systematically *lower* for stego than for
   clean. In principle an overseer could exploit this by flagging
   batches whose statistic is anomalously *small* as well as anomalously
   *large* — a two-sided test would turn a 0.155 AUROC into ~0.85.
   This suggests a cheap, concrete upgrade to any frequency-based
   CoT auditor: treat *under-dispersion* as suspicious too, not just
   over-dispersion.
2. **The bigram surprisal detector also collapses** from 1.000 to
   0.439. A balanced template distribution reconstructs the clean
   bigram distribution to first order; only higher-order correlations
   (e.g. bit-stream autocorrelation across positions) still give the
   adversary away. A future detector explicitly targeting autocorrelation
   would be the right follow-up.

These results go beyond a benchmark: they identify a concrete,
exploitable weakness in the dominant "rate-bias" family of CoT
auditors, plus a cheap mitigation (two-sided tests) and a direction for
the next generation of detector (autocorrelation / block-entropy).

## Limits of the toy

This is a lab instrument, not a production detector. Several
simplifications are intentional but worth naming:

- **Grammar is closed and small.** Real CoTs have unbounded paraphrase
  classes; the white-box detectors here get template knowledge for
  free, which they would not in practice. The bigram detector is the
  closest thing to a realistic baseline.
- **Payloads loop.** A real adversary would use a keyed PRNG to
  whiten the channel; our looping makes some attacks easier for the
  detector than they should be. The balanced-payload experiment is
  the exception — it's *harder* than a keyed channel would be for any
  rate-based detector.
- **No RL in the loop.** Motwani et al. (2024) showed that stego
  capacity grows sharply when the cover model is RL-trained with a
  reward that prefers smuggled bits. This test-bed does not train
  anything; the encoders here are hand-built strategies that a real
  model *could* implement, not ones it was optimized to find.
- **Single-batch detection only.** Real auditors get a stream of CoTs
  across time and can exploit temporal drift. The capacity curve
  experiment is a crude proxy for this.

## Suggested next steps (what this points at)

1. **Two-sided detectors.** Retrofit every rate-based detector here
   with an under-dispersion arm. This is a one-line change that
   directly closes the balanced-payload evasion in §3.
2. **Autocorrelation / block-entropy tests.** A balanced payload
   kills frequency but leaves position-dependent structure. A detector
   that computes lag-k autocorrelation of the binary decision sequence
   across positions in a CoT would catch the leak bigram surprisal
   misses.
3. **Paraphrase-invariance probes.** Roger & Greenblatt's paraphrase
   defense is complementary: if a paraphraser re-samples template
   choices, any channel built on template choice is destroyed. A
   small experiment in this test-bed would compare
   "detect-then-reject" vs. "paraphrase-then-forward" in terms of
   information survival.
4. **Scale up the cover grammar.** Swap the running-total problem
   for a small real reasoning corpus (e.g. GSM8K-style problems with
   paraphrase augmentation) and replace the bigram model with an
   n-gram or small neural LM. The detector interfaces do not change.
5. **Train a model organism.** RL-fine-tune a small open-weight LM
   with a shaped reward that rewards answer correctness *and* smuggled
   bit recovery, then run this toolbox against its outputs. The
   detectors here are the right first-pass control in that setup.
